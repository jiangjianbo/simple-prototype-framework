# 原型系统设计文档

**版本**：v1.0
**定位**：JSON 驱动、可嵌套、类型感知的静态前端原型系统
**技术栈**：Vue 3 + Vite + TypeScript + Element Plus + ts-morph

---

## 1. 概述

### 1.1 目标

构建一个 JSON 驱动的静态前端原型系统。开发者只需编写两类文件——**TypeScript 模型定义**（描述数据结构）和 **JSON 页面配置**（描述界面）——系统即可自动组装为一个可运行的 Vue 3 应用，用于中后台系统的界面原型快速搭建与演示。

### 1.2 核心设计理念

- **一切皆组件**：除顶层 HTML 骨架外，`desktop` / `page` / `component` / `element` 四级节点均可互相嵌套，统一由渲染器递归处理。
- **JSON 即页面**：页面结构、菜单树、数据引用全部由 JSON 声明，无需编写页面代码。
- **类型驱动渲染**：字段的 UI 组件由 **TypeScript 类型**（构建期提取的元数据）+ **上下文模式**（edit / readonly / disabled / preview）共同决策。
- **多系统隔离**：每个子系统（如 `back`、`userfront`）拥有独立的模型、菜单、页面与资源目录。
- **覆盖式导航**：`@goto` 跳转按目标层级覆盖当前视图子树，而非 URL 路由。

### 1.3 非目标

- 不追求运行时全动态能力（如运行时修改 schema 并热更新）。
- 不处理真实后端数据接口（原型阶段数据为静态 mock，通过 JSON 声明）。
- 不做可视化拖拽编辑器（JSON 手写即可）。

## 2. 技术选型

| 层次       | 选择                              | 说明                                                         |
| ---------- | --------------------------------- | ------------------------------------------------------------ |
| 框架       | **Vue 3**                         | 动态组件 `<component :is>` + 动态插槽 `v-slot:[name]` 天然支持递归与插槽分发 |
| 构建工具   | **Vite**                          | 快速开发体验，原生 TS 支持                                   |
| UI 库      | **Element Plus**                  | 全量组件注册为 JSON 可用的 `component`                       |
| 类型解析   | **ts-morph**                      | 构建阶段扫描 `*.ts` 模型文件，提取字段类型与装饰器           |
| 元数据格式 | **metadata.json**                 | 构建产物，运行时读取                                         |
| 语言       | **TypeScript**                    | 全栈 TS                                                      |
| 状态管理   | **Vue reactive / provide-inject** | 原型阶段无需 Pinia，轻量即可                                 |

> **注**：不使用 `tst-reflect`。运行时反射在 Vite/esbuild 下集成成本高且不稳定；采用「构建期 ts-morph 扫描 → 生成 JSON 元数据 → 运行时读取」的解耦方案。

## 4. JSON DSL 规范

### 4.1 节点通用结构

```typescript
interface Node {
  type?: 'desktop' | 'page' | 'component' | 'element';  // 默认 'element'
  component: string;                    // 必须：注册表中的 Vue 组件名
  slot?: string;                        // 投递到父组件的命名插槽，省略 = default
  id?: string;                          // page / desktop 常用，用于导航
  data?: any;                           // 数据绑定，支持 @ / @@ / / / @/ 前缀
  mode?: 'edit' | 'readonly' | 'disabled' | 'preview';
  children?: Node[];                    // 子节点
  '@goto'?: string;                     // 点击跳转的目标 id
  [key: string]: any;                   // 其他属性透传为组件 props
}
```

### 4.2 四级语义

| type        | 语义         | 递归行为                            | 常见组件                           |
| ----------- | ------------ | ----------------------------------- | ---------------------------------- |
| `desktop`   | 整体框架     | 容器，递归 children                 | `app-layout` |
| `page`      | 页面         | 容器，递归 children                 | `page-view` / `form`            |
| `component` | 组件         | 容器，递归 children（按 slot 分发） | `table` / `card` / `tabs`          |
| `element`   | 元素（叶子） | **不递归**，直接渲染                | `text` / `button` / `icon`         |

> 若 `type` 省略，默认 `element`，不处理 `children`。若叶子组件（如 `table`）需要"配置型子节点"（如 `column`），由组件内部遍历 `children` 自行解析，而非渲染器递归。

### 4.3 引用前缀规范

| 前缀                | 含义                         | 解析阶段            | 示例                                         |
| ------------------- | ---------------------------- | ------------------- | -------------------------------------------- |
| `@title`            | 引用**当前或祖先节点**的属性 | JSON 加载后、渲染前 | 从节点树上取 `title`                         |
| `@@User`            | 引用**类型元数据**           | 渲染该节点时        | 查 `metadata.json` 中的 `back.User`          |
| `@@User.name`       | 引用类型字段（一级）         | 渲染该节点时        | 展开为 `User` 的 `name` 字段                 |
| `@@User.roles.name` | 引用嵌套字段（多级）         | 渲染该节点时        | 展开为 `Role` 的 `name` 字段，标记 `inArray` |
| `/back.menu.json`   | 引用**文件内容**             | JSON 加载阶段       | 文件内容内联                                 |
| `@/a/b/c/brain.png` | 引用**本地资源路径**         | 渲染阶段            | 作为 `src` 交给组件                          |

**查找规则**：

- `@xxx`：当前节点 → 逐级向上 → 直到 `desktop` 根，未找到则 `undefined`。
- `@@Type`：全局元数据注册表，与节点位置无关，查表时自动加系统前缀。
- 嵌套文件引用（`menu.json` 内的 `@/...`）统一相对**原型系统根目录**解析。


### 4.6 角色定义与菜单角色权限

菜单 JSON 顶层新增可选 `roles` 数组声明角色体系，菜单项新增可选 `roles` 白名单：

```json
{
  "roles": [
    { "id": "admin", "label": "安全管理员", "description": "全部功能" },
    { "id": "auditor", "label": "审计员" }
  ],
  "items": [
    { "label": "用户编辑", "pageId": "user-info", "roles": ["admin"] }
  ]
}
```

| 规则 | 设计 |
| --- | --- |
| 启用开关 | 顶层 `roles` 缺省 = 不启用角色体系（菜单对所有人生效） |
| 默认角色 | `roles` 数组第一个为进入系统时的默认角色，存于 `appState.role` |
| 可见性 | 菜单项 `roles` 缺省 = 全角色可见；写了 = 白名单（递归作用于任意层级） |
| 分组折叠 | 纯分组（无 `pageId`）的可见子项被过滤为空时整组隐藏；可点击分组保留为叶子 |
| 权限丢失回退 | `setRole` 后当前页不可见时自动导航到该角色第一个可见页面 |
| 边界 | 过滤仅作用于菜单树（`filterMenuByRole`），不拦截 `@goto` / URL 直达——原型演示语义，非安全边界 |

实现位于 `src/framework/role.ts`（纯函数过滤）与 `LayoutControls.vue` 中的角色切换下拉（仅 `roles` 存在时渲染）；控件簇由各场景布局的 `controls` 槽回落承载。

## 5. 渲染架构

### 5.1 渲染流程

```
启动
  │
  ▼
加载 metadata.json
  │
  ▼
加载系统配置（back / userfront）
  │
  ▼
合并 page.json 列表 → 建立 id → Node 索引
加载 menu.json → 建立菜单树
  │
  ▼
递归解析引用（/ 文件、@ 属性）→ 得到完整节点树
  │
  ▼
渲染 desktop（Vue 递归）
  │  ├─ 每个节点：根据 type 决定是否递归 children
  │  ├─ 每个节点：按 slot 分组 children，投递到父组件插槽
  │  ├─ data === '@@Xxx' → 交给 field-mapper 展开字段
  │  └─ 点击菜单/按钮 @goto → navigate() → 覆盖式替换
  ▼
DOM
```

### 5.2 渲染器核心

```typescript
function renderNode(node: Node, ctx: RenderContext): VNode {
  const impl = registry[node.component];
  if (!impl) return h(MissingComponent, { message: `[未知组件: ${node.component}]` });

  // 1. 解析 data 引用
  const data = resolveData(node.data, ctx, node);

  // 2. 若是 @@Xxx，交给 field-mapper 展开为字段组件列表
  if (typeof node.data === 'string' && node.data.startsWith('@@')) {
    return renderTypeFields(node, data, ctx);
  }

  // 3. 组装 props
  const props: Record<string, any> = { ...stripMeta(node), data };
  if (node['@goto']) {
    props.onGoto = () => navigate(node['@goto']!, node, ctx);
  }
  if (node.mode === 'disabled' && isFormLikeComponent(node.component)) {
    props.disabled = true;
  }

  // 4. type === 'element' → 不递归 children
  if (node.type === 'element' || !node.type) {
    return h(impl, props);
  }

  // 5. 容器节点：按 slot 分组 children，生成动态插槽
  const slotGroups = groupBySlot(node.children || []);
  const slots: Record<string, () => VNode[]> = {};
  for (const [slotName, children] of slotGroups) {
    slots[slotName] = () => children.map(c => renderNode(c, ctx));
  }
  return h(impl, props, slots);
}
```

### 5.3 渲染上下文

```typescript
interface RenderContext {
  system: string;                   // 'back' | 'userfront'
  currentPageId: string;
  mode?: Mode;                      // 从父级传播
  metadata: MetadataRegistry;       // @@ 引用来源
  nodeIndex: Map<string, Node>;     // id → Node 索引（用于导航）
  resolveAttr(path: string, scope: Node): any;
}
```

`mode` 通过 `provide/inject` 向下传播：`table` 节点 `mode: readonly` → 其子字段默认只读；子节点可通过 JSON 显式 `mode` 覆盖父级。

### 5.4 覆盖式导航（`@goto` 与菜单点击统一入口）

**核心规则**：`@goto` 的目标层级决定覆盖范围。

| 当前节点    | 跳转目标 `type` | 覆盖行为                                             |
| ----------- | --------------- | ---------------------------------------------------- |
| `page`      | `page`          | 用目标 page **原地替换**当前 page 节点，slot 不变    |
| `page`      | `desktop`       | 用目标 desktop **替换整个 desktop 节点**             |
| `component` | `component`     | 替换当前 component 节点                              |
| `element`   | `element`       | 替换当前 element                                     |
| 跨层级      | 更高层级        | 向上找到第一个 `type === target.type` 的祖先，替换之 |

```typescript
// navigation.ts
export function navigate(targetId: string, currentNode: Node, ctx: RenderContext) {
  const target = ctx.nodeIndex.get(targetId);
  if (!target) return;

  if (target.type === currentNode.type) {
    ctx.replaceNode(currentNode.path, target);
  } else if (target.type === 'desktop') {
    ctx.replaceDesktop(target);
  } else {
    const ancestor = ctx.findAncestorOfType(currentNode, target.type!);
    if (ancestor) ctx.replaceNode(ancestor.path, target);
  }

  // 同步面包屑
  if (target.type === 'page') {
    pushCrumb({ pageId: targetId, title: target.title ?? targetId });
  } else if (target.type === 'desktop') {
    resetCrumbs([{ pageId: targetId, title: target.title ?? targetId }]);
  }
}
```

菜单点击与 `@goto` 走同一个 `navigate` 函数，保证行为一致。

### 6.2 扫描脚本（`src/metadata/generate-metadata.ts`）

```typescript
import { Project } from 'ts-morph';

const project = new Project({ tsConfigFilePath: 'tsconfig.json' });
const result: Record<string, TypeMeta> = {};

for (const source of project.getSourceFiles('systems/*/models/*.ts')) {
  const system = source.getFilePath().match(/systems\/([^/]+)\//)?.[1] ?? '';
  for (const cls of source.getClasses()) {
    const fields: FieldMeta[] = [];
    for (const prop of cls.getProperties()) {
      const uiOptions = prop.getDecorator('UiOptions');
      const args = uiOptions?.getArguments()[0];
      const rawType = prop.getType().getText();   // 'string' | 'number' | 'Role[]' | ...
      fields.push({
        name: prop.getName(),
        type: normalizeType(rawType, system),      // 加系统前缀
        isArray: rawType.endsWith('[]'),
        label: extractProp(args, 'label') ?? prop.getName(),
        desc: extractProp(args, 'desc'),
      });
    }
    result[`${system}.${cls.getName()}`] = {
      name: cls.getName(),
      system,
      fields,
    };
  }
}

function normalizeType(t: string, system: string) {
  const base = t.replace('[]', '').trim();
  // 基础类型不动，对象引用加系统前缀
  const primitives = ['string', 'number', 'boolean', 'Date', 'null', 'undefined'];
  if (primitives.includes(base)) return t.replace('[]', '');
  return t.replace(base, `${system}.${base}`).replace('[]', '');
}

writeFileSync('public/metadata.json', JSON.stringify(result, null, 2));
```

### 6.5 嵌套路径展开（`@@User.name` / `@@User.roles.name`）

`@@User` 展开全部字段；`@@User.name` 展开一级字段；`@@User.roles.name` 展开嵌套字段（考虑数组）。

```typescript
function expandPath(
  rootType: string,
  path: string[],
  ctx: RenderContext
): FieldMeta[] {
  const [head, ...rest] = path;
  const typeMeta = ctx.metadata[rootType];
  if (!typeMeta) return [];

  // path 为空：展开全部字段
  if (!head) return typeMeta.fields;

  const field = typeMeta.fields.find(f => f.name === head);
  if (!field) return [];

  // path 只有一级：返回该字段本身
  if (rest.length === 0) return [field];

  // 递归下钻
  const refType = field.type;
  if (ctx.metadata[refType]) {
    const nested = expandPath(refType, rest, ctx);
    return field.isArray
      ? nested.map(n => ({ ...n, inArray: true, arraySource: head }))
      : nested;
  }

  return [];
}
```

| JSON 写法                   | 展开结果                                                     |
| --------------------------- | ------------------------------------------------------------ |
| `data: "@@User"`            | `User` 全部字段                                              |
| `data: "@@User.name"`       | 仅 `name` 字段                                               |
| `data: "@@User.roles.name"` | `Role.name` 字段，标记 `inArray: true`、`arraySource: "roles"` |

`table` 收到带 `inArray` 的字段时，自动生成多值列（`ElTableColumn` 的 children 或自定义模板）；`form` 收到 `inArray` 时生成多行输入 / 标签输入。

### 7.4 类型 → 组件映射决策矩阵

**影响因素**：

| 因素         | 来源                 | 取值                                                       |
| ------------ | -------------------- | ---------------------------------------------------------- |
| 字段类型     | `metadata.json`      | `string` / `number` / `boolean` / `Date` / 引用类型 / 数组 |
| 上下文模式   | 父组件 `mode` 传播   | `edit` / `readonly` / `disabled` / `preview`               |
| 节点显式声明 | JSON `component`     | 存在则直接使用                                             |
| 是否在表格中 | 父组件类型为 `table` | `true` / `false`                                           |
| 是否在表单中 | 父组件类型为 `form`  | `true` / `false`                                           |

**mode 的四种取值**：

| mode       | 语义                           | 典型场景        |
| ---------- | ------------------------------ | --------------- |
| `edit`     | 可编辑（默认）                 | 新建 / 编辑表单 |
| `readonly` | 只读，无交互                   | 详情页展示      |
| `disabled` | 禁用，有表单外观但不可改       | 权限不足        |
| `preview`  | 预览，可能带轻量交互（如链接） | 表格摘要字段    |

**决策优先级（从高到低）**：

1. JSON 节点显式 `component` → 直接使用。
2. `mode === 'preview'` 且字段类型为 `string` → `link`。
3. `mode === 'readonly'` → 只读映射表。
4. `mode === 'disabled'` → 编辑映射表 + 自动注入 `disabled: true`。
5. `mode === 'edit'`（默认）→ 编辑映射表。
6. 数组字段在表格中 → 由 `table` 组件内部处理多值列。
7. 未知类型 → `missing-component`。

```typescript
type Mode = 'edit' | 'readonly' | 'disabled' | 'preview';

const editMap: Record<string, string> = {
  string: 'input',
  number: 'input-number',
  boolean: 'switch',
  Date: 'date-picker',
};

const readonlyMap: Record<string, string> = {
  string: 'text',
  number: 'text',
  boolean: 'boolean-badge',
  Date: 'text',
};

export function resolveFieldComponent(
  fieldType: string,
  mode: Mode = 'edit',
  context: { inTable?: boolean; inForm?: boolean } = {}
): string {
  if (mode === 'preview' && fieldType === 'string') return 'link';
  if (mode === 'readonly') return readonlyMap[fieldType] ?? 'missing-component';
  if (mode === 'disabled') return editMap[fieldType] ?? 'missing-component';
  return editMap[fieldType] ?? 'missing-component';
}
```

**disabled 模式的自动注入**：`renderNode` 中若 `mode === 'disabled'` 且组件属于表单类（`input`、`input-number`、`switch`、`date-picker`、`select` 等），自动合并 `props.disabled = true`。表单类组件列表以注册表中的子集为准，可用 `Set` 维护。

## 8. 引用解析

### 8.1 解析时机

| 引用         | 时机           | 实现                         |
| ------------ | -------------- | ---------------------------- |
| `/file.json` | 加载阶段       | `fetch` 读取并内联到当前节点 |
| `@attr`      | 加载后、渲染前 | 沿节点树向上查找             |
| `@@Type`     | 渲染该节点时   | 查 `metadata.json`           |
| `@/path`     | 渲染该节点时   | 原样交给组件（`img.src` 等） |

### 8.2 加载器

```typescript
async function loadSchema(path: string): Promise<any> {
  const raw = await fetch(path).then(r => r.json());
  return preprocess(raw, path);
}

async function preprocess(node: any, basePath: string): Promise<any> {
  if (Array.isArray(node)) return Promise.all(node.map(n => preprocess(n, basePath)));
  const out = { ...node };
  if (typeof out.data === 'string' && out.data.startsWith('/')) {
    out.data = await loadSchema(out.data.slice(1));
  }
  if (out.children) out.children = await preprocess(out.children, basePath);
  return out;
}
```

### 8.3 `@` 属性解析

```typescript
function resolveAttr(path: string, node: Node, scopeStack: Node[]): any {
  // 当前节点
  if (path in node) return node[path];
  // 逐级向上
  for (let i = scopeStack.length - 1; i >= 0; i--) {
    if (path in scopeStack[i]) return scopeStack[i][path];
  }
  return undefined;
}
```

### 9.2 面包屑自维护（`breadcrumb-store.ts`）

面包屑**不由 JSON 手写**，而是从导航状态自动派生。

```typescript
import { reactive } from 'vue';

interface Crumb {
  pageId: string;
  title: string;
}

export const breadcrumbState = reactive({
  trail: [] as Crumb[],
});

export function pushCrumb(crumb: Crumb) {
  const idx = breadcrumbState.trail.findIndex(c => c.pageId === crumb.pageId);
  if (idx > -1) {
    breadcrumbState.trail.splice(idx + 1);   // 截断到该位置之后
    breadcrumbState.trail[idx] = crumb;      // 更新标题
  } else {
    breadcrumbState.trail.push(crumb);
  }
}

export function resetCrumbs(crumbs: Crumb[] = []) {
  breadcrumbState.trail = [...crumbs];
}
```

**触发时机**：

| 事件                 | 面包屑行为                                                 |
| -------------------- | ---------------------------------------------------------- |
| 进入 `page`          | `pushCrumb({ pageId, title })`，title 取 page 节点 `title` |
| 点击面包屑某项       | `navigate(pageId)` → 触发截断                              |
| `@goto` 同类覆盖     | 同菜单点击                                                 |
| `@goto` 到 `desktop` | `resetCrumbs()`                                            |

`Breadcrumb.vue`（契约名 `breadcrumb`）只消费 `breadcrumbState.trail` 渲染面包屑链（shadcn 套件用 reka-ui；plain 套件为斜杠分隔文本），点击非末项调用 `navigate` 回跳并截断。JSON 中只需：

```json
{ "slot": "breadcrumb", "component": "breadcrumb" }
```

- 所有 `page` 节点加载后注册到 `nodeIndex`。
- 渲染 `desktop` 时，只渲染 `id === currentPageId` 的 page 节点，其他跳过。
- 菜单点击 → `navigate(pageId)` → 响应式重新渲染。

## 13. 页面状态机（真值表）

### 13.1 定位与作用

页面状态机用于描述一个页面内**多个组件之间的状态协同**：什么条件触发状态转移、进入某状态后各组件应呈现什么属性。它以 markdown 真值表书写，与页面 JSON 分离，避免把交互逻辑塞进 JSON 结构。

- **一页一表**：默认每个 `page` 节点对应一个 `.sm.md` 文件。
- **多表逃生口**：页面极大时可拆多表，每表声明 `scope`，同一属性只允许一个表写入。
- **触发 / 响应分离**：表的上半区是条件（读），下半区是动作（写），两区语义不同，同一组件可在两区各出现一次。
- **事件驱动**：状态转移只由声明的事件触发，不做属性变化的连续求值，避免循环。

---

### 13.2 表格结构

一张真值表由**表头 + 分区线 + 两个区域**组成：

```markdown
# 页面状态机：user-info

| 组件 / 事件 | 状态A（初始） | 状态B | 状态C |
|---|---|---|---|
| userInfo | .lock==true | .lock==false | .lock==true |
| auditor | .name==$currentUserName | .name==$currentUserName | .name!=$currentUserName |
| btnEdit | @click | | |
| btnSubmit | | @click | @click |
| === | === | === | === |
| txtUser | .readOnly=true | .readOnly=false | .readOnly=true |
| txtDescription | .readOnly=false | .readOnly=false | .readOnly=true |
| buttonSubmit | .enabled=false | .enabled=true | .enabled=false |
| form | | | .reset() |
```

| 元素               | 规范                                                         |
| ------------------ | ------------------------------------------------------------ |
| 表头第一列         | 固定文字 `组件 / 事件`                                       |
| 表头状态列         | 列名即状态 id；标注 `（初始）` 的列为初始状态，未标注取第一列 |
| 分区线             | 整行所有单元格均为 `===`，分隔触发区与响应区                 |
| 触发区行           | 第一列为组件名；状态列为 `.prop` 条件表达式或 `@event` 事件标记 |
| 响应区行           | 第一列为组件名；状态列为 `.prop=val;...` 赋值 / 方法调用语句 |
| 空单元格（触发区） | 该状态不约束此组件                                           |
| 空单元格（响应区） | 进入该状态时不改动此组件                                     |

**组件名约定**：表格第一列的组件名必须等于页面 JSON 中对应节点的 `id` 字段。渲染器维护 `id → 组件实例 / 响应式数据` 的映射，供状态机求值使用。

---

### 13.3 单元格语法

#### 3.1 触发区

| 写法                             | 含义                                       |
| -------------------------------- | ------------------------------------------ |
| `@click` / `@change` / `@submit` | 声明该状态响应此事件                       |
| `.lock==true`                    | 条件：属性等于某值                         |
| `.age>18`                        | 条件：比较运算                             |
| `.name=="abc"`                   | 条件：字符串比较（`==` / `===` 均可）      |
| `.a==1 && .b==2`                 | 条件：逻辑与                               |
| `.a==1 \|\| .b==2`               | 条件：逻辑或                               |
| `.isValid()`                     | 条件：方法调用返回真值                     |
| `.name==$currentUserName`        | `$` 开头为系统常量，原型阶段保留原文不解析 |

- 一行是"该组件在此状态下的完整条件"，多条件用 `&&` / `||` 组合，**整体求值为真**才算满足。
- 事件行（`@event`）与条件行可同时存在于同一状态的不同组件上，互不干扰。

#### 3.2 响应区

| 写法                            | 含义                        |
| ------------------------------- | --------------------------- |
| `.readOnly=true`                | 赋值：设为某值              |
| `.value=0` / `.text="提示"`     | 赋值：数字 / 字符串         |
| `.reset()`                      | 方法调用                    |
| `.readOnly=true;.enabled=false` | 多语句：按 `;` 从左到右执行 |
| `.visible=false;.clear()`       | 赋值与方法混用              |

- 响应区**不使用 `$` 常量**，也不需要。
- 多条语句按分号分割，执行顺序即书写顺序。

#### 3.3 事件多列声明语义

若状态 A 和状态 B 都声明了 `btnSubmit@click`：

- 用户点击 `btnSubmit` → 遍历所有声明 `btnSubmit@click` 的状态（A、B）
- 对每个候选状态，检查其触发区中**所有属性条件**
- 恰好一个候选状态条件全部成立 → 转移；0 个 → 事件被忽略；多个 → 状态机定义有歧义，运行时报错

事件触发**只校验属性条件，不校验同状态下其他事件是否发生**。

### 13.4 表达式解析

#### 4.1 属性前缀替换

单元格内以 `.` 开头的属性片段，需要展开为 `组件名.属性` 的完整路径后再求值。使用以下正则完成前缀替换：

```typescript
const PROP_RE = /(^|[^\w."'])(\.\w+)/g;

function qualify(component: string, expr: string): string {
  return expr.replace(PROP_RE, (_, prefix, prop) => prefix + component + prop);
}
```

**正则说明**：`(^|[^\w."'])` 要求 `.prop` 前面是字符串开头，或一个**既不是单词字符也不是点号**的字符（如空格、括号、运算符）。这样可以：

- 匹配开头处的 `.lock`（如表达式本身以 `.` 起头）
- 匹配运算符后的 `.lock`（如 `&& .lock`、`== .lock`）
- **不匹配**已完整的 `userInfo.lock`（`.` 前是 `o`，属于单词字符）
- **不匹配**链式访问 `a.b.c` 中的 `.b` 和 `.c`（`.` 前是单词字符）
- **不匹配**数字小数 `1.5` 中的 `.5`（`.` 前是数字）

#### 4.2 前缀替换示例

| 组件       | 原始表达式                      | 替换后                                        |
| ---------- | ------------------------------- | --------------------------------------------- |
| `userInfo` | `.lock==true && .name=="abc"`   | `userInfo.lock==true && userInfo.name=="abc"` |
| `txtUser`  | `.readOnly=true;.enabled=false` | `txtUser.readOnly=true;txtUser.enabled=false` |
| `form`     | `.reset()`                      | `form.reset()`                                |
| `btnEdit`  | `@click`                        | `@click`（事件标记不做替换）                  |

#### 4.3 字符串内容说明

如果字符串字面量内出现以 `.` 开头的内容（如 `.tip==".hidden"`），`PROP_RE` 会把字符串中的 `.hidden` 也替换掉。规范建议：

- 字符串值内避免以 `.` 开头（改用 `"hidden"` 或其他写法）
- 若确需保留，解析器可在 `qualify` 之前先按引号切分字符串，仅对非字符串片段做替换

#### 4.4 单元格分类

```typescript
type CellKind = 'event' | 'cond' | 'action' | 'empty';

function classify(raw: string, section: 'trigger' | 'response'): CellKind {
  const s = raw.trim();
  if (!s) return 'empty';
  if (s.startsWith('@')) return 'event';
  return section === 'trigger' ? 'cond' : 'action';
}
```

### 13.5 状态机语义

#### 5.1 状态与初始状态

- **状态 = 列**，列名即状态 id。
- 初始状态取表头中标注 `（初始）` 的列；未标注则取第一列。
- 运行时维护隐式变量 `$state`，记录当前状态 id。

#### 5.2 事件驱动的转移流程

```
事件 E = { 组件 C, 事件名 ev } 发生
  │
  ▼
候选状态集合 = { S | trigger.events[S][C] 包含 ev }
  │
  ▼
对每个候选状态 S，检查 trigger.conds[S] 全部条件
  （每条条件已 qualify，对 ctx.scope 求值）
  │
  ▼
匹配状态集合 = 通过全部条件检查的候选状态
  │
  ├─ 恰好 1 个 → $state = S，执行 response.actions[S]
  ├─ 0 个     → 不转移，事件忽略
  └─ 多个     → 抛出错误，状态机定义存在歧义
```

#### 5.3 响应执行

进入目标状态后，按表格顺序遍历 `response.actions[S]`，逐条执行。执行过程中产生的事件**不立即**触发新的转移，排队到下一 tick，避免同 tick 内循环。

#### 5.4 幂等转移

若事件触发后得到的目标状态与当前 `$state` 相同，则视为幂等：

- 若响应区为空 → 不产生任何变化
- 若响应区非空 → 重新执行响应（允许"重置"语义）

### 13.6 与页面 JSON 的集成

#### 6.1 单表声明

页面节点新增可选字段 `stateMachine`：

```json

  "type": "page",
  "id": "user-info",
  "component": "page-view",
  "stateMachine": "/systems/back/schemas/pages/user-info.sm.md",
  "children": [
    { "component": "form",   "id": "userInfo",  "data": "@@User" },

    { "component": "button", "id": "btnEdit",   "text": "编辑" },
    { "component": "button", "id": "btnSubmit", "text": "提交" },

    { "component": "input",  "id": "txtDescription" },
    { "component": "button", "id": "buttonSubmit", "text": "保存" }

```

- 值为 `.sm.md` 文件的路径（相对于原型系统根目录，与 `/xxx.json` 引用规则一致）。

#### 6.2 多表声明（逃生口）

```json

  { "scope": "table", "src": "/systems/back/schemas/pages/user-info.table.sm.md" }
```

- 每张表只允许写入 `scope` 前缀下的组件（如 `form.*`）。

- 单表场景推荐直接使用字符串形式。

#### 6.3 事件注入

渲染器在渲染带 `id` 的交互组件时，若该页面启用了状态机，则为组件自动注入事件回调。例如 `btnEdit` 节点：

```typescript

  ...,
  onClick: () => engine.onEvent('btnEdit', 'click'),
};
```

事件名与组件注册表对应，使用方无需在 JSON 中声明事件。

### 13.7 解析产物与运行时 AST

#### 7.1 解析结果

```typescript
interface StateMachine {
  states: string[];                                   // 状态 id 列表
  initial: string;                                    // 初始状态
  trigger: {
    events: Record<string, Record<string, string[]>>; // state → 组件 → 事件名列表
    conds:  Record<string, Record<string, string>>;   // state → 组件 → 已 qualify 的条件表达式
  };
  response: {
    actions: Record<string, Record<string, string[]>>; // state → 组件 → 语句列表
  };
}
```

- `events` 与 `conds` 都以状态为一级键、组件为二级键。
- `conds` 每格是**一条**（可能含 `&&` / `||` 的复合）表达式。
- `actions` 每格已按 `;` 拆分为语句数组，元素已 qualify。

#### 7.2 markdown 解析流程

```
读取 .sm.md
  │
  ▼
markdown-it 解析 → 找到首个 table token
  │
  ▼
提取表头行 → 第一列为 "组件 / 事件"，其余为状态 id
提取数据行 → 定位 "===" 分区行
  │
  ▼
上半区：逐行 → 组件名、逐列 → 单元格分类（empty/event/cond）
        cond 单元格调用 qualify(component, raw)
下半区：逐行 → 组件名、逐列 → 单元格分类（empty/action）
        action 单元格按 ";" 拆分，每段调用 qualify
  │
  ▼
StateMachine AST
```

#### 7.3 运行时引擎

```typescript
class StateMachineEngine {
  private state: string;

  constructor(
    private sm: StateMachine,
    private scope: Record<string, any>,
    private resolveComponent: (id: string) => any
  ) {
    this.state = sm.initial;
    this.applyResponse(this.state);
  }

  onEvent(component: string, event: string) {
    const candidates = this.sm.states.filter(s =>
      this.sm.trigger.events[s]?.[component]?.includes(event)
    );
    const matched = candidates.filter(s => {
      const cond = this.sm.trigger.conds[s]?.[component];
      if (!cond) return true;
      return this.evalCond(cond);
    });
    if (matched.length > 1) {
      throw new Error(`事件 ${component}@${event} 匹配多个状态: ${matched.join(', ')}`);
    }
    if (matched.length === 1) {
      this.state = matched[0];
      this.applyResponse(this.state);
    }
  }

  private evalCond(expr: string): boolean {
    return new Function('scope', `with(scope){ return (${expr}) }`)(this.scope);
  }

  private applyResponse(state: string) {
    const actions = this.sm.response.actions[state] ?? {};
    for (const stmts of Object.values(actions)) {
      for (const stmt of stmts) {
        new Function('scope', `with(scope){ ${stmt} }`)(this.scope);
      }
    }
  }
}
```

**求值器约定**：

- `scope` 是一个 `reactive` 对象，键为组件 id，值为该组件的响应式数据或组件实例。
- `with(scope)` 让已 qualify 的表达式（如 `userInfo.lock`）能直接访问。
- 原型阶段可用 `new Function`，生产环境替换为 AST 求值器并禁用 `with` 与全局作用域。

### 13.8 冲突与静态检查

| 检查项                                        | 级别       | 处理                                  |
| --------------------------------------------- | ---------- | ------------------------------------- |
| 同一状态下响应区对同一组件出现多行            | 错误       | markdown 表结构应保证一行一组件的响应 |
| 事件 E 在多个状态声明，且属性条件可能同时成立 | 运行期错误 | 事件触发时若匹配多个状态则抛错        |
| 表达式引用的组件 id 不在页面 JSON 中          | 加载期错误 | 对照页面节点 id 校验并阻断            |
| 表达式引用的属性不在组件 props 中             | 加载期警告 | 仅提示，不阻断                        |
| 多表场景下同一组件属性被多个表写入            | 加载期错误 | 列出冲突属性与表名                    |
| 表格缺少分区线                                | 加载期错误 | `.sm.md` 必须包含 `===` 分隔行        |
| 表头状态列为空或重复                          | 加载期错误 | 状态 id 必须唯一非空                  |
| 未标注初始状态                                | 警告       | 取第一列作为初始状态                  |

### 13.9 完整示例

#### 9.1 页面 JSON（节选）

```json
{
  "type": "page",
  "id": "user-info",
  "component": "page-view",
  "title": "用户编辑",
  "stateMachine": "/systems/back/schemas/pages/user-info.sm.md",
  "children": [
    { "component": "form",   "id": "userInfo",       "data": "@@User", "mode": "readonly" },
    { "component": "form",   "id": "auditor",        "data": "@@Auditor" },
    { "component": "button", "id": "btnEdit",        "text": "编辑" },
    { "component": "button", "id": "btnSubmit",      "text": "提交", "variant": "primary" },
    { "component": "input",  "id": "txtUser",        "label": "用户名" },
    { "component": "input",  "id": "txtDescription", "label": "描述" },
    { "component": "button", "id": "buttonSubmit",   "text": "保存" }
  ]
}
```

#### 9.2 状态机文件 `user-info.sm.md`

```markdown
# 页面状态机：user-info

| 组件 / 事件 | 浏览（初始） | 编辑中 | 审核中 |
|---|---|---|---|
| userInfo | .lock==true | .lock==false | .lock==true |
| auditor | .name==$currentUserName | .name==$currentUserName | .name!=$currentUserName |
| btnEdit | @click | | |
| btnSubmit | | @click | @click |
| === | === | === | === |
| txtUser | .readOnly=true | .readOnly=false | .readOnly=true |
| txtDescription | .readOnly=true | .readOnly=false | .readOnly=true |
| buttonSubmit | .enabled=false | .enabled=true | .enabled=false |
| form | | | .reset() |
```

#### 9.3 执行过程

1. **初始化** → `$state = "浏览"`，执行响应：`txtUser.readOnly=true`、`txtDescription.readOnly=true`、`buttonSubmit.enabled=false`。
2. **点击 `btnEdit`** → 只有"浏览"状态声明了 `btnEdit@click`，且条件 `userInfo.lock==true && auditor.name==$currentUserName` 成立 → 转移到"编辑中" → 执行：`txtUser.readOnly=false`、`txtDescription.readOnly=false`、`buttonSubmit.enabled=true`。
3. **点击 `btnSubmit`（在"编辑中"状态下）** → 候选状态为"编辑中"和"审核中"。检查"编辑中"：`userInfo.lock==false`（此时 lock 为 false）成立 → 但当前已在"编辑中"，触发幂等重入 → 重新执行"编辑中"响应（无副作用）。
4. **假设 `userInfo.lock` 被外部置为 `true`** → 再点击 `btnSubmit` → "编辑中"条件 `userInfo.lock==false` 不成立；"审核中"条件 `userInfo.lock==true && auditor.name!=$currentUserName` 成立 → 转移到"审核中" → 执行：`txtUser.readOnly=true`、`txtDescription.readOnly=true`、`buttonSubmit.enabled=false`、`form.reset()`。

#### 9.4 关于重叠的处理

- `auditor` 在触发区出现（`auditor.name==...`），`form` 在响应区出现（`form.reset()`），同一组件在不同区各出现一次，**不冲突**。
- `userInfo` 既在触发区被读（`.lock==...`），也在响应区可能的扩展中被写，两区语义独立。
- `btnSubmit` 在响应区可写 `.enabled`，也可在其他状态的触发区被读，同样不冲突。

## 14. 静态构建（file:// 可直开的多系统静态页）

### 14.1 目标与约束

交付原型时常常只有文件系统（拷贝/邮件/U 盘），要求**双击 `dist/<系统id>/index.html` 即可完整浏览**。这带来一条硬约束：浏览器在 `file://` 协议下会同时拦截 ① 外部 `<script type="module" src>`（CORS）与 ② `fetch()` 本地文件——所以静态页必须把 **JS、CSS、全部配置与数据** 内联进单个 HTML 文件。

### 14.2 构建管线

`npm run build` = `gen:metadata` + `vite build` + `scripts/build-static.ts`：

1. 从 `dist/index.html` 提取打包产物，生成「内联壳」（`<style>` + `<script type="module">`）；
2. 对每个系统：读盘模拟 fetch，复用运行时 `preprocessNode` 把 `/file.json` 引用全部内联；
3. 收集状态机 `.sm.md` 源文与 `@/` 资源（图片转 base64 data URL）；
4. 注入 `<script type="application/json" id="pp-bootstrap">` 数据块，输出 `dist/<系统id>/index.html`。

`vite.config.ts` 设 `base: './'`，保证服务器模式入口 `dist/index.html` 使用相对路径。

### 14.3 bootstrap 契约

```
{ "system": "back",
  "files":   { "/metadata.json": "<原文>", "/systems/index.json": "<原文>",
               "/systems/back/back.menu.json": "<原文>", ... ".sm.md 源文" },
  "assets":  { "back/brain.png": "data:image/png;base64,..." } }
```

- `files` 以**运行时 fetch 的原始 URL 为键**，因此 `boot()` / `loadSystem()` / 状态机加载的现有代码路径零改动——`fetchJson` / `fetchText` / `resolveAssetUrl`（`resolver.ts`）只在最前面加一步「先查 bootstrap」。
- JSON 内联安全：数据块中所有 `<` 转义为 `\u003c`（防 `</script>` 提前闭合）；内联 JS 中 `</script` → `<\/script`、`<!--` → `<\!--`。
- 页面title 替换为「系统名 · 原型系统」。

### 14.4 静态模式下的系统切换与角色

- `loadSystem(id)` 检测到目标 ≠ 当前 `boot.system` 时转发给 `goToStaticSystem(id)` → `window.location.assign('../<id>/index.html')`（兄弟页面跳转，保持顶栏下拉切换 UX；测试中经 `setStaticNavigator` 注入以便断言）。
- 角色配置随菜单 JSON 内嵌，静态页中切换器与菜单过滤与服务器模式行为一致。

### 14.5 边界

静态页是**构建期快照**：改 `systems/` 下任何内容需重新 `npm run build`；单文件体积约 0.7 MB（含全部 JS/CSS 与资源 data URL）属预期。

## 15. 套件（Kit）与主题（Theme）

### 15.1 定位

- **套件** = 组件契约的一套实现：`Record<契约名, Component>` 的（部分）映射。契约名是稳定的语义槽位（`button`、`app-layout`、`stat-card`…），应用按系统声明用哪套实现。命名弃用早期草案「组件集」。
- **主题** = CSS 变量配色方案（`src/style.css` 的 `[data-theme]` 块），与套件**正交**：2 套件 × 3 主题任意组合。

### 15.2 解析架构

```
registry.ts
├── COMPONENT_ALIASES      旧名 → 规范名（兼容层，永不删除）
├── KITS = { shadcn, plain }
├── resolveComponent(name) 别名归一 → 当前套件 → 默认套件（shadcn）兜底
└── registry = Proxy       renderer 既有的 registry[name] 读法 transparently 走解析
```

- **部分覆盖是正式特性**：套件只实现想覆盖的契约名，其余回落默认套件。继承的逻辑复合件（schema-form / table / tabs / field-value）内部经 `resolveComponent` 取原语，因此自动随套件变形——新套件只需实现原子层 + 壳层。
- **切套件 = 整树重挂载**：`App.vue` 以 `${system}:${kit}` 为 NodeRenderer 的 key；`kitState.kit` 变更即触发重挂载，引擎与 store 不动。**切主题 = 改根元素属性**（`html.dark` 或 `html[data-theme]`），即时生效、跨套件通用。
- **声明与运行时**：`systems/index.json` 的 `defaultKit/defaultTheme` + 条目级 `kit/theme`（优先级：条目 > 清单 > 内置 shadcn/light），`loadSystem` 仅在**切换到不同系统**时应用声明值——同系统内的手动切换不被覆盖。切换控件簇为契约组件 `layout-controls`（`LayoutControls.vue`，套件无关，契约 `select` 渲染），由各场景布局的 `controls` 槽回落承载（槽写 children 可整簇替换）。
- **手工下架**：清单条目 `enabled: false` 在 `boot` 阶段即被过滤——不进入 `appState.systems`（原型切换下拉的数据源，启动默认顺延为第一个启用项），静态构建同样跳过；缺省视为启用。
- **静态构建**：manifest 原样内嵌进 bootstrap，静态页按声明组合启动（如 userfront 直开即 plain/warm）。

### 15.3 内置套件

| id | 名称 | 视觉 | 覆盖 |
|---|---|---|---|
| `shadcn` | 精致 Shadcn | reka-ui + Tailwind，圆角/阴影/动效 | 全量（约 62 个契约名），兼任兜底 |
| `plain` | 极简 Plain | 原生元素，直角/细边框/无阴影 | 原子层 + 壳层约 35 个契约名，其余继承 |
| `deckurate` | Deckurate 靛蓝 | 复刻 Deckurate-Front：灰底描边按钮、胶囊徽标、下划线标签、大写表头、语义色统计卡、顶栏三段式布局 | 约 9 个覆盖，其余继承；配 `deckurate` 主题（indigo） |

新增套件/主题的步骤、契约参数规范见 **doc/组件规范.md** §7 / §8。

## 附录 A：JSON 节点字段速查

| 字段        | 必须 | 说明                                                   |
| ----------- | ---- | ------------------------------------------------------ |
| `type`      | 否   | `desktop / page / component / element`，默认 `element` |
| `component` | 是   | 注册表中的组件名                                       |
| `slot`      | 否   | 父组件插槽名，省略为 default                           |
| `id`        | 否   | 节点唯一标识，导航用                                   |
| `data`      | 否   | 支持 `@ / @@ / / / @/` 前缀                            |
| `mode`      | 否   | `edit / readonly / disabled / preview`                 |
| `children`  | 否   | 子节点数组                                             |
| `@goto`     | 否   | 点击跳转的目标 id                                      |
| 其他        | 否   | 透传为组件 props                                       |

## 附录 B：引用前缀速查

| 前缀 | 含义                       | 示例                           |
| ---- | -------------------------- | ------------------------------ |
| `@`  | 节点属性引用               | `@title`                       |
| `@@` | 类型元数据引用（支持多级） | `@@User` / `@@User.roles.name` |
| `/`  | 文件内容引用               | `/back.menu.json`              |
| `@/` | 本地资源路径引用           | `@/a/b/c/brain.png`            |

## 附录 C：术语表

| 术语               | 含义                                                 |
| ------------------ | ---------------------------------------------------- |
| 系统（system）     | 一个独立的原型子系统，如 `back`、`userfront`         |
| 节点（node）       | JSON 树中的一个对象，对应一个 Vue 组件实例           |
| 层级（type）       | 节点的语义层级：desktop / page / component / element |
| 模式（mode）       | 渲染上下文状态，影响组件选择                         |
| 覆盖式导航         | 按目标层级替换当前视图子树的导航方式                 |
| 元数据（metadata） | ts-morph 从模型文件提取的类型信息                    |
| 契约名             | 组件的语义注册名（kebab-case），JSON `component` 的合法值（§7.1） |
| 场景布局（Scene Layout） | 每个界面的最底层布局；一系统多场景（app-layout / login-layout / screen-layout），统一 `controls` 槽承载切换控件簇（§7.1、doc/组件规范.md §3.8） |
| 套件（kit）        | 组件契约的一套实现，可部分覆盖，按系统声明（§15）    |
| 主题（theme）      | CSS 变量配色方案，与套件正交、自由组合（§15）        |
