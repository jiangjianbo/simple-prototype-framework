# 组件规范（契约 × 套件 × 主题）

> 版本：2026-11 · 适用于 `src/registry.ts` 契约注册表 + `src/kits/*` 套件体系（设计文档 §7.1 / §15）
>
> 本文档回答四个问题：
> 1. **组件叫什么** —— 契约名（kebab-case，一眼可读，与 JSON `component` 字段一致）；
> 2. **组件怎么用** —— 每个契约名的参数（props）、插槽（slot）、v-model 类型；
> 3. **同一组件多种长相** —— 套件（Kit）机制：一套契约，多套实现，应用按系统选择；
> 4. **配色怎么换** —— 主题（Theme）机制：CSS 变量配色，与套件正交、自由组合。

---

## 1. 三层模型：契约名 → 套件 → 主题

```
JSON 节点                契约注册表                     浏览器实际渲染
component: "button"  →  resolveComponent("button")  →  当前套件的 Button 实现
                          （别名归一 → 当前套件 → 默认套件兜底）      ×  当前主题的 CSS 变量
```

| 层 | 是什么 | 在哪定义 | 谁选择 |
|---|---|---|---|
| **契约名** | 组件的语义名字与参数/插槽约定（本文档） | `src/registry.ts` + 本文档 | JSON 作者使用 |
| **套件 Kit** | 一份 `Record<契约名, 组件实现>` 映射，可部分覆盖 | `src/kits/shadcn.ts`（默认+兜底）、`src/kits/plain.ts` | `systems/index.json` 按系统声明 `kit` 字段，顶栏可运行时切换 |
| **主题 Theme** | 一块 CSS 变量配色，与套件无关 | `src/style.css` 的 `[data-theme]` 块 | `systems/index.json` 按系统声明 `theme` 字段，顶栏可运行时切换 |

关键规则：

- **套件可以部分覆盖**。套件里没写的契约名自动回落到默认套件（shadcn）。继承下来的逻辑复合件（schema-form / table / tabs / field-value 等）内部通过契约解析取原语，因此在新套件下自动换用新套件的原语——**写一个 20 组件的极简套件，不需要重写表单引擎、表格引擎和图表**。
- **套件与主题正交**。2 套件 × 3 主题 = 6 种组合，任意搭配即时生效。
- **切套件 = 整树重挂载**（App 以 `系统:套件` 为 key），**切主题 = 只改根元素属性**（毫秒级）。
- **清单声明是基线，运行时切换是临时态**。顶栏手动切套件/主题后，切换到别的系统会恢复目标系统声明的组合。

## 2. 通用约定

### 2.1 命名规范

- 契约名一律 **kebab-case 语义名词**，要求「一眼看出用途」：`app-layout`、`stat-card`、`boolean-badge`、`date-picker`。
- 不用实现细节/品牌做名（历史上 `frame-with-title-and-menu-footer` 这类名字已废弃，见 §6 别名表）。
- 同义旧名（`tag`、`divider`、`form`）保留为别名，等价解析到规范名。
- 一个语义一个名字；新组件必须先在本文档登记再实现。

### 2.2 Props 约定

| 约定 | 说明 |
|---|---|
| **class** | 所有组件接受 `class` 字符串，合并到根元素（不覆盖内置类） |
| **text** | 展示型组件（text/heading/badge/button/card-title…）支持 `text` 字符串快捷内容；也可用默认插槽 |
| **data** | 渲染器会把节点 `data` 字段解析后作为 props 注入（`@@`/`@`/`@/` 引用），展示型组件普遍接受 `data` 作为内容来源，优先级高于 `text` |
| **modelValue / update:modelValue** | 受控控件统一 v-model 契约，类型见 §4.3 |
| **disabled** | 表单类控件统一支持；`mode: "disabled"` 时渲染器自动注入 |
| **options** | 选项类控件统一结构 `{ label: string, value: string|number, disabled?: boolean }[]` |

渲染器保留字段（不会透传为 props）：`type`、`component`、`slot`、`children`、`data`、`mode`、`@goto`、`stateMachine`、`constants`；其余节点字段全部原样透传。

### 2.3 插槽约定

- **默认插槽**：容器组件的 `children` 按 `slot` 字段分组投递，缺省投到默认插槽。
- **具名插槽**：在 children 上写 `"slot": "名称"`，如 `app-layout` 的 `title/menu/breadcrumb/controls/content/sidebar/footer`、`card` 的 `header/footer`、`schema-form` 的 `footer`、`table` 的 `toolbar`（由 `column` 配置外的子节点自动拆出）。
- 两个特例不走插槽分发：`tabs`（内部消化 `tab-pane` 子节点）与 `table` 的 `column` 配置数组。

### 2.4 组件分层

| 层 | 归属 | 例子 |
|---|---|---|
| **原子层** | 每个套件各自实现 | button、input、card、badge、table-raw 族 |
| **逻辑复合层** | 全局一份（套件间继承），内部经契约解析用原语 | schema-form、table（DataTable）、tabs、descriptions、图表、field-value |
| **壳层** | 每个套件各自实现（整壳替换） | app-layout、login-layout、screen-layout（场景布局）、page-view、nav-menu、breadcrumb、stat-card、alert、empty |

### 3.8 场景布局（Scene Layout）与壳层

**场景布局** = 每个界面的最底层布局；一个系统可有多个场景（主界面、登录页、数据大屏各自成壳）。统一规范：

- 每个场景布局必须提供 **`controls` 槽**承载原型切换控件簇（系统 / 套件 / 主题 / 角色四下拉 + 设计说明开关、全部标注按钮 + 头像）；槽留空回落渲染契约组件 `layout-controls`，写 children 则整簇替换。
- 布局只用语义主题变量（`bg-background` / `border` 等）保证跨套件跨主题；面板类区域经契约组件（如 `card`）实现套件自适应。
- 候选场景（未内置，按需加契约 + 两套件实现）：`wizard-layout` 分步向导（步骤条 + 上一步/下一步 footer）、`doc-layout` 文档/详情（返回栏 + 窄栏正文）、`blank-layout` 空白自由布局（引导页 / 打印视图）。

| 契约名 | 套件 | 插槽 / 参数 | 说明 |
|---|---|---|---|
| `app-layout` | 🟦 | 插槽：`icon` `title` `menu` `breadcrumb` `controls` `content` `sidebar` `footer` | 主应用框架（侧栏菜单 + 顶栏 + 内容/侧栏）；`app-shell` 旧名 |
| `login-layout` | | 插槽：`brand` `title` `form` `controls` `footer` | 登录 / 注册入口页：右上角 controls + 居中契约 `card` 面板；plain 套件回落（面板随套件变形） |
| `screen-layout` | | 插槽：`icon` `title` `controls` 默认（内容网格）`footer` | 数据大屏 / 监控墙：顶部标题栏 + 全宽内容区，建议配 dark 主题；plain 套件回落 |
| `layout-controls` | | —（自读全局状态） | 切换控件簇（系统/套件/主题/角色四下拉 + 设计说明面板开关、全部标注入口 + 头像），套件无关、经契约 `select`/`button` 自适应；各布局 controls 槽的回落内容 |
| `page-view` | 🟦 | 参数：`title`、`description`；插槽：默认 | 页头（h1 + 描述）+ 页面级状态机错误/警告横幅 + `document.title` 同步（`page-default` 旧名） |
| `nav-menu` | 🟦 | 参数：`title`；菜单项 `count`（右侧弱化计数数字） | 消费 `appState.menu`，按当前角色过滤，点击 `navigate(pageId)`（`menu-tree` 旧名） |
| `breadcrumb` | 🟦 | 无参 | 消费 `breadcrumbState.trail`，点击非末项回跳截断（`breadcrumb-auto` 旧名） |

## 4. 重点细节

### 4.1 渲染器注入的通用 props（组件实现者须知）

`renderer.ts` 在 `h(impl, props)` 前统一注入：

- `data`：`data`/`model` 字段经引用解析后的结果（`@@` 展开 → fields + 数据、`@` 属性引用、`@/` 资源 URL）；
- `mode`：`edit`/`readonly`/`disabled`/`preview`，沿树继承、节点可覆盖；
- `disabled`：`mode: "disabled"` 时对 FORM_LIKE 组件自动注入；状态机 `enabled:false / readOnly:true` 同样注入；
- `__nodes`：仅 `tabs`（INTERNAL_CHILDREN），children 原始节点数组。

### 4.2 `table` 的 column 配置

```json
{
  "component": "table", "title": "订单", "data": "/systems/x/data/orders.json",
  "column": [
    { "field": "@@Order.id" },
    { "field": "@@Order.amount", "align": "right", "width": 120 },
    { "field": "status", "label": "状态" },
    { "component": "button", "text": "新建" }
  ]
}
```

- `field: "@@Type.name"` → 取该字段元数据（label + 类型感知格式化）；
- 纯 `field` 字符串 → 手工列；其余对象/组件节点 → `toolbar` 插槽。

### 4.3 受控控件 v-model 类型速查

| 控件 | 入参类型 | 出参类型 |
|---|---|---|
| input / textarea / select / radio-group / date-picker | `string` | `string` |
| input-number | `number \| null` | `number \| null` |
| switch | `boolean` | `boolean` |
| checkbox | `boolean \| 'indeterminate'` | `boolean` |
| slider | `number[]` | `number[]` |

状态机 binding 的 `value` 直写这些类型；schema-form 的 `values` 仓库同构。

### 4.4 未知组件兜底

`component` 在注册表解析不到时渲染 `missing-component` 占位，不阻断整页渲染。别名表（§6）保证旧配置平滑升级。

## 5. 内部原语（不面向 JSON，但契约化）

逻辑复合件内部通过 `resolveComponent()` 取用以下原语，因此随套件变形：

| 原语契约名 | 消费方 | 说明 |
|---|---|---|
| `input` `textarea` `input-number` `switch` `select` `radio-group` `checkbox` `slider` `date-picker` `label` | schema-form | 表单控件 |
| `table-raw` 族 + `badge` `button` `input` | table（DataTable） | 表格结构与工具条 |
| `tabs-root` `tabs-list` `tabs-trigger` `tabs-content` | tabs | 标签页结构 |
| `badge` `boolean-badge` | field-value | 值展示 |

这些名字同样注册在 registry 上（JSON 里直接写也能渲染），但语义上属于实现细节，**新增 JSON 页面请优先使用 §3 的面向作者组件**。

| `field-placeholder` | `field-list` | 2026-11 重命名 |
| `readonly-boolean` | `boolean-badge` | 2026-11 重命名 |

## 7. 套件（Kit）开发指南

**内置套件**：

| id | 名称 | 视觉语言 | 覆盖范围 |
|---|---|---|---|
| `shadcn` | 精致 Shadcn | reka-ui + Tailwind，圆角、阴影、动效 | 全量（约 62 个契约名），兼任兜底 |
| `plain` | 极简 Plain | 原生元素，直角、细边框、无阴影 | 原子层 + 壳层约 35 个契约名，其余继承 shadcn |
| `deckurate` | Deckurate 靛蓝 | 复刻 Deckurate-Front 基础组件：灰底描边按钮、胶囊徽标、下划线标签页、大写表头、语义色统计卡、顶栏三段式布局 | 约 9 个覆盖 + 全部扩展契约经兜底，配 `deckurate` 主题 |

**新增套件（如 `terminal`）三步**：

1. 建 `src/kits/terminal.ts`，导出 `TERMINAL_KIT: Record<string, Component>`——只写想覆盖的契约名，其余自动回落 shadcn；
2. 在 `src/registry.ts` 的 `KIT_LIST` 与 `KITS` 各登记一行（id/label/description）；
3. （可选）在 `systems/index.json` 给某个系统声明 `"kit": "terminal"` 验证。

实现要求：

- 同一契约名的实现必须满足本文档该组件的 **props/slot/v-model 契约**（这是"套件可互换"的硬约束）；
- 用语义工具类（`bg-background`、`text-muted-foreground`、`border`）而非硬编码色值，保证任意主题可用；
- 逻辑复合件（schema-form/table/tabs/descriptions/图表/field-value）**不要**在套件里重写——通过契约原语自动变形；只有壳层与纯展示组件需要套件自实现。

**按系统声明**（`systems/index.json`）：

```json
{
  "defaultKit": "shadcn", "defaultTheme": "light",
  "systems": [
    { "id": "back", "label": "数据安全大脑", "kit": "shadcn", "theme": "light" },
    { "id": "userfront", "label": "用户中心", "kit": "plain", "theme": "warm" }
  ]
}
```

优先级：条目 `kit`/`theme` > 清单 `defaultKit`/`defaultTheme` > 内置缺省（shadcn/light）。顶栏下拉可运行时切换；切套件整树重挂载，切主题即时生效；切换系统恢复该系统声明值。

## 8. 主题（Theme）规范

主题 = `src/style.css` 中的一块 CSS 变量，**与套件正交**（plain 套件同样用语义变量，三主题通吃）。

**内置主题**：

| id | label | 生效方式 |
|---|---|---|
| `light` | 浅色 | 默认变量（`:root`） |
| `dark` | 深色 | `html.dark` class（Tailwind `@custom-variant dark`，支持 `dark:` 工具类） |
| `warm` | 暖沙 | `html[data-theme='warm']` 属性块 |
| `deckurate` | 靛蓝 Deckurate | `html[data-theme='deckurate']`（indigo 主色 + 紫系图表调色板） |

**变量清单**（一个主题必须定义全部）：

`--background` `--foreground` `--card` `--card-foreground` `--popover` `--popover-foreground` `--primary` `--primary-foreground` `--secondary` `--secondary-foreground` `--muted` `--muted-foreground` `--accent` `--accent-foreground` `--destructive` `--destructive-foreground` `--border` `--input` `--ring` `--radius` `--sidebar` `--sidebar-foreground` `--chart-1..5`

**新增主题（如 `ocean`）三步**：

1. `src/style.css` 加 `html[data-theme='ocean'] { ... }` 变量块（照抄 warm 块改色值）；
2. `src/framework/kit-store.ts` 的 `THEMES` 数组登记 `{ id: 'ocean', label: '海洋' }`；
3. 顶栏主题下拉即出现该选项；可在 `systems/index.json` 按系统声明。

> 约定：深色变体一律走 `.dark` class；其余主题走 `data-theme` 属性。未登记 id 写到 `data-theme` 上不报错，只是没有匹配变量块（回落浅色）。

## 9. 修改本规范的流程

1. 在本文档 §3 登记：契约名、参数、插槽、示例；
2. `src/kits/shadcn.ts` 添加默认实现（新组件必须先有默认实现）；
3. 需要跨套件变形的逻辑复合件内部用 `resolveComponent('<name>')` 取用；
4. 跑 `npm test`（契约回归：`tests/kits.test.ts` 有别名与套件切换断言）；
5. 若是重命名：在 §6 别名表加一行旧名映射，**永不删除**。
