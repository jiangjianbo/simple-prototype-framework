# 原型编写操作手册

> 本手册是原型系统的**完整编写语法参考**：目录怎么摆、JSON 怎么写、每个组件接什么属性、状态机表格怎么画。
> 所有语法均以仓库内两个示例系统（`systems/back`、`systems/userfront`）为事实样本，可直接对照抄改。
> 设计背景与原理见 `doc/原型系统设计文档.md`；本手册只讲「怎么写」。

---

## 0. 一分钟心智模型

一个原型 = 一个或多个「系统」。写一个系统只需要五样东西，**全部放在 `systems/<系统id>/` 下**：

```
systems/
  index.json              ← 系统清单：声明有哪些系统
  <系统id>/
    <系统id>.menu.json    ← 左侧菜单
    <系统id>.page.json    ← 页面与组件（核心，90% 的工作量在这）
    models/*.ts           ← 类型模型（生成字段元数据，驱动表格列与表单）
    pages/*.sm.md         ← 页面状态机（可选，交互流转）
    data/*.json           ← mock 数据（可选，被 /file 引用内联）
    assets/*              ← 图片等静态资源（可选，@/ 引用）
```

**目录路径 = 访问 URL**：`systems/back/data/orders.json` ⇔ `/systems/back/data/orders.json`。页面 JSON 里的 `/file` 引用直接写这个路径即可。

改完即生效：`npm run dev` 下保存文件 → 浏览器刷新可见（`models/*.ts` 有改动时元数据会在下次 dev/build 自动重新生成，也可手动 `npm run gen:metadata`）。

## 1. 类型模型 `models/*.ts`

用普通 TS class 描述业务对象，`@UiOptions` 提供 UI 文案。构建期 `ts-morph` 扫描生成 `public/metadata.json`（**生成物，不要手改**）。

```ts
// systems/back/models/User.ts
export class User {
  @UiOptions({ label: '姓名' })
  name: string;

  @UiOptions({ label: '年龄' })
  age: number;

  @UiOptions({ label: '在职' })
  isActive: boolean;

  @UiOptions({ label: '入职日期' })
  createdAt: Date;

  @UiOptions({ label: '角色' })
  roles: Role[];          // 引用类型：指向同目录其它模型 class

  @UiOptions({ label: '备注', desc: '输入框里的占位提示' })
  comment: string;
}
```

规则：

| 项 | 说明 |
|---|---|
| 支持的基础类型 | `string` / `number` / `boolean` / `Date`（数组写 `T[]`） |
| 引用类型 | 写其它 class 名（如 `Role`），生成时自动加系统前缀成 `back.Role` |
| `@UiOptions({ label })` | 字段显示名；省略时用字段名 |
| `@UiOptions({ desc })` | 字段辅助说明（edit 表单中显示在控件下方） |
| 类名即类型 id | 页面里写 `@@User` 引用；跨系统不冲突（元数据按 `系统.类名` 存储） |

元数据决定两件事：
- **表格/描述列表的列**：`data: "@@User"` 自动展开全部字段为列；
- **表单的控件**：类型 × 模式决策矩阵（见 §6.2）。

## 2. 系统清单 `systems/index.json`

```json
{
  "systems": [
    { "id": "back", "label": "数据安全大脑" },
    { "id": "userfront", "label": "用户中心" }
  ]
}
```

`id` 对应目录名；`label` 显示在顶栏系统切换器。第一个系统为启动默认。切换系统会完整重载（销毁状态机引擎 → 重新拉取配置 → 重建页面树索引）。

## 3. 菜单 `<系统id>.menu.json`

```json
{
  "title": "数据安全大脑",
  "items": [
    { "label": "安全概览", "pageId": "dashboard", "icon": "layout-dashboard" },
    { "label": "用户管理", "icon": "users", "children": [
      { "label": "用户列表", "pageId": "user-list", "icon": "list-todo" },
      { "label": "用户编辑", "pageId": "user-info", "icon": "pencil" }
    ]},
    { "label": "订单管理", "pageId": "order-list" }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `label` | ✓ | 菜单文字；有 `pageId` 时点击导航 |
| `pageId` | | 目标 page 节点的 `id`（纯激活切换，见 §8） |
| `icon` | | lucide 图标名（如 `users`、`settings`） |
| `children` | | 子菜单，可无限嵌套 |
| `title` | | 侧栏顶部标题（可省，通常由 desktop 的 title 插槽承担） |

## 4. 页面配置 `<系统id>.page.json`

### 4.1 节点模型（四级）

```
desktop → page → component → element
```

- 一切皆节点。**缺省 `type` 视为 `component`**（可有 children）；显式写 `"type": "element"` 才是不递归的叶子。
- `page` 节点始终挂在 desktop 树上，由菜单驱动「激活切换」。
- 每个节点除了 `children` 还可以通过 `slot` 声明自己进入父组件的哪个插槽。

### 4.2 desktop 节点（两种形态均可）

形态 A —— 包装式（back）：

```json
{ "desktop": { "type": "desktop", "id": "back-desktop", "component": "frame-with-title-and-menu-footer", "children": [ ... ] } }
```

形态 B —— 根节点即 desktop（userfront）：

```json
{ "type": "desktop", "id": "userfront-desktop", "component": "frame-with-title-and-menu-footer", "children": [ ... ] }
```

desktop 用 `frame-with-title-and-menu-footer` 布局，children 按插槽投递：

| slot | 内容 |
|---|---|
| `icon` | 侧栏顶部图标（如 `{"component":"icon","data":"@/logo.svg"}`） |
| `title` | 侧栏标题文字 |
| `menu` | 固定放 `{"component":"menu-tree"}` |
| `breadcrumb` | 固定放 `{"component":"breadcrumb-auto"}` |
| `sidebar` | 右侧栏（可选；整棵子树在所有页面共享，如安全公告卡片） |
| `footer` | 侧栏底部文字 |
| `content` | 所有 `type:"page"` 节点放这里 |

### 4.3 page 节点

```json
{
  "type": "page",
  "id": "user-info",
  "slot": "content",
  "title": "用户编辑",
  "description": "页面顶部描述行（可选）",
  "component": "page-default",
  "stateMachine": "/systems/back/pages/user-info.sm.md",
  "constants": { "$currentUserName": "管理员" },
  "children": [ ...页面内容... ]
}
```

| 属性 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 全 desktop 内唯一；菜单/`@goto`/面包屑/状态机都靠它 |
| `title` | ✓ | h1 与面包屑文案 |
| `component` | ✓ | 现用 `page-default`（自动渲染 h1 + description + children） |
| `slot` | | 一般写 `"content"` |
| `stateMachine` | | `.sm.md` 路径；多条写数组 `[{"scope":"...","src":"..."}]` |
| `constants` | | 注入状态机 scope 的页面常量（键建议 `$` 开头，如 `$currentUserName`） |

### 4.4 节点通用属性

任何节点可写的字段（**框架保留字段**不会透传给组件，其余全部原样透传为组件 props）：

| 字段 | 用途 |
|---|---|
| `type` | 节点层级（desktop/page/component/element） |
| `component` | 注册组件名（见 §7） |
| `slot` | 投递进父组件的命名插槽 |
| `children` | 子节点数组 |
| `id` | 节点标识；页面状态机按它绑定组件；导航按它寻址 |
| `data` | 数据来源（可写四种引用，见 §5）；也是多数展示组件的内容入口 |
| `mode` | `"edit" \| "readonly" \| "disabled" \| "preview"`，子树继承 |
| `@goto` | 点击时导航到目标 id（常配 button） |
| `stateMachine` / `constants` | 仅 page 节点 |
| `column` | 仅 table：列配置数组（特殊子节点） |
| 其它任意键 | 直接透传，如 `text`、`title`、`variant`、`height`… |

### 4.5 插槽机制

渲染器把 children 按 `slot`（缺省 `"default"`）分组投递。各组件声明的插槽：

| 组件 | 插槽 |
|---|---|
| `frame-with-title-and-menu-footer` | `icon` `title` `menu` `breadcrumb` `content` `sidebar` `footer` |
| `card` | `header`（放 card-header）、`default`（放内容）、`footer` |
| `form` | `footer`（操作按钮行，children 里写 `"slot":"footer"`） |
| `tabs` | 不走插槽分发——children 必须是 `tab-pane` 节点（内部消化） |

典型卡片写法：

```json
{
  "component": "card",
  "children": [
    { "slot": "header", "component": "card-header", "children": [
      { "component": "card-title", "text": "基础配置" },
      { "component": "card-description", "text": "表单说明文字" }
    ]},
    { "slot": "default", "component": "form", "data": "@@Setting", "mode": "edit" }
  ]
}
```

## 5. 引用语法（五种前缀）

| 写法 | 名称 | 时机 | 示例 |
|---|---|---|---|
| `/path/file.json` | 文件引用 | 加载期内联（改数据无需改页面 JSON） | `"data": "/systems/back/data/orders.json"` |
| `@@Type` | 类型引用 | 渲染期展开字段元数据 | `"data": "@@User"`（表格/描述自动成列） |
| `@@Type.field` | 单字段引用 | 渲染期取单字段元数据 | `"field": "@@MyOrder.amount"`（列） |
| `@/file.png` | 本系统资源 | 渲染期解析为 `/systems/<系统id>/assets/file.png` | `"data": "@/logo.svg"` |
| `@attr` | 属性引用 | 渲染期沿祖先链找节点属性 | `"data": "@title"`（取祖先的 title） |

**文件引用可内联的属性**：`data`、`rows`、`value`、`items`、`options`。`value` 为对象时其内部键值也允许 `/file` 引用。

```json
{ "component": "table", "rows": "/systems/back/data/orders.json" },
{ "component": "form", "model": "@@Profile", "value": "/systems/userfront/data/profile.json" }
```

> 注：`model` 是 `data` 的别名（表单场景更达意），二者等价。

## 6. 模式（mode）与类型感知

### 6.1 mode 继承与注入

- 子节点缺省继承父节点的 `mode`，可在任意节点显式覆盖。
- `mode: "disabled"` 时，表单类组件（input/textarea/input-number/switch/checkbox/radio-group/select/date-picker/slider/form）**自动注入 `disabled: true`**——适合「权限不足只读」场景。

### 6.2 表单决策矩阵（字段类型 × mode → 控件）

| 类型 | edit（编辑） | readonly（只读展示） | disabled（禁用编辑） |
|---|---|---|---|
| string | input | 文本 | input + disabled |
| number | input-number | 文本（千分位） | input-number + disabled |
| boolean | switch | 是/否 徽章 | switch + disabled |
| Date | date-picker | 格式化文本 | date-picker + disabled |
| 引用/数组 | 占位提示 | 名称/徽章组 | 同 readonly |

`mode: "preview"` 下 string 显示为链接。

### 6.3 值的展示规则（table 单元格 / descriptions / field-value 通用）

布尔→「是/否」徽章；数组→徽章组；引用对象→名称；日期→格式化；数字→千分位。写页面时**不需要**为这些做格式化配置。

## 7. 组件手册

> 按 `component` 注册名列出。`data` 列的组件均支持 §5 的引用语法。示例只写节点本体，放入任意 page/desktop 的 children 即可。

### 7.1 布局

**row** —— 栅格行（CSS grid）

| 属性 | 说明 |
|---|---|
| `columns` | 等分列数，如 `"columns": 4`（缺省 1） |
| `template` | 自定义列宽模板，如 `"template": "1.75fr 1fr"`、`"auto 1fr"`（与 columns 二选一，template 优先） |
| `gap` | 间距 px（缺省 16） |

```json
{ "component": "row", "template": "1.6fr 1fr", "children": [ /* 两个 card */ ] }
```

**card 系** —— `card` / `card-header` / `card-title` / `card-description` / `card-content` / `card-footer`（后五个直接作 children 放入对应 slot，见 §4.5）。

**separator / divider** —— 分隔线（两个名字等价）。
**tabs / tab-pane** —— 标签页：

```json
{ "component": "tabs", "children": [
  { "component": "tab-pane", "label": "基本信息", "children": [ /*...*/ ] },
  { "component": "tab-pane", "label": "日志", "children": [ /*...*/ ] }
] }
```

### 7.2 基础展示

| 组件 | 属性 | 说明 |
|---|---|---|
| `text` | `text` 或 `data`、`size`(`xs/sm/base/lg/xl/2xl`)、`muted`、`strong` | 万能文本 |
| `heading` | `text`/`data`、`level`(1-4) | 标题 |
| `link` | `text`/`data`、`href` | 链接 |
| `icon` | `name`（lucide 名）或 `data:"@/x.svg"`、`size`(`xs/sm/md/lg`)、`boxed` | 图标/图片图标 |
| `image` | `src`/`data`、`alt`、`rounded` | 图片 |
| `badge` / `tag` | `text`（两名字等价） | 徽章 |
| `alert` | `variant`(`default/info/success/warning/destructive`)、`title`、`description`、`icon` | 通告 |
| `progress` | `value`、`max`(缺省 100) | 进度条 |
| `avatar` | `src`/`data`、`fallback`(文字兜底)、`alt` | 头像 |
| `empty` | `description`、`icon` | 空状态 |
| `skeleton` | — | 骨架屏 |
| `stat-card` | `title`、`value`、`delta`、`tone`(`default/up/down`)、`icon`、`hint` | 统计卡 |

```json
{ "component": "stat-card", "title": "接入资产", "value": 1284, "delta": "12%", "tone": "up", "icon": "server", "hint": "较上月新增 138 台" }
```

**descriptions** —— 只读字段描述列表：

| 属性 | 说明 |
|---|---|
| `data` / `model` | `"@@User"` 自动按元数据成行（推荐） |
| `value` | 数据对象（可 `/file` 引用） |
| `columns` | 列数（缺省 2） |
| `mode` | 建议显式 `"readonly"` |

```json
{ "component": "descriptions", "data": "@@User", "mode": "readonly",
  "value": { "name": "张伟", "age": 32 } }
```

### 7.3 表单

**form（= schema-form）** —— 模型驱动表单，字段由 `@@Type` 元数据 + 决策矩阵生成：

| 属性 | 说明 |
|---|---|
| `data` / `model` | `"@@Setting"` 声明字段集（元数据来源） |
| `value` | 播种值：对象字面量或 `/file.json` |
| `mode` | `edit` / `readonly` / `disabled`（缺省 edit，受父级继承） |
| `columns` | 字段栅格列数（缺省 2） |
| `fieldOptions` | 字段级选项覆盖：`{ "theme": [{"label":"浅色","value":"light"}, ...] }`，使 string 字段渲染为 select |
| children `slot:"footer"` | 底部按钮行 |

```json
{ "component": "form", "id": "profileForm", "model": "@@Profile", "mode": "edit", "columns": 2,
  "value": "/systems/userfront/data/profile.json",
  "fieldOptions": { "theme": [
    { "label": "浅色", "value": "light" },
    { "label": "深色", "value": "dark" }
  ]},
  "children": [
    { "slot": "footer", "component": "row", "template": "auto auto", "gap": 10, "children": [
      { "component": "button", "text": "保存修改", "variant": "primary" },
      { "component": "button", "text": "重置", "variant": "outline" }
    ]}
  ]}
```

**单控件**也可直接用：`input` `textarea` `input-number`(min/max/step) `switch` `checkbox` `select`(options) `radio-group`(options) `slider` `date-picker` `label` `form-item`(label/desc/required)。启用状态机的页面里，给控件写 `id` 即被绑定（见 §9.4）。

**button** —— `text`（文案）、`variant`(`primary/secondary/outline/destructive/ghost/link`)、`size`；`@goto` 触发导航（见 §8）。

### 7.4 数据表格 table（TanStack 封装，特性按需启用）

| 属性 | 说明 |
|---|---|
| `title` | 工具栏标题（右侧自动带行数徽标） |
| `rows` | 数据数组或 `/file.json` |
| `data` / `column` | 列来源，三种写法见下 |
| `searchable` | 关键词搜索框（全局包含匹配） |
| `sortable` | 列头点击排序 |
| `paginated` | 分页（缺省开，pageSize 10） |
| `pageSize` | 每页行数 |
| `groupBy` | 分组字段名（开启分组行模型） |
| `aggregations` | 列级聚合 `{ "amount": "sum", "qty": "sum" }`，支持 `sum/count/avg/min/max` |
| `emptyText` | 空态文案 |

**列的三种写法**（`column` 数组内的节点：能识别字段引用的进列配置，其余节点渲染进工具栏插槽）：

```json
"column": [
  { "data": "@@MyOrder" },                                  // ① 整表展开：全部字段成列
  { "field": "product", "label": "商品" },                   // ② 手写列：字段名 + 显示名
  { "component": "field-placeholder", "field": "@@MyOrder.amount",
    "align": "right" },                                      // ③ 单字段引用：带元数据（label/类型格式化）
  { "component": "button", "text": "导出", "variant": "outline" }  // 非列节点 → 工具栏按钮
]
```

列可选属性：`align`(`left/right/center`)、`width`(px)。分组行首列自动显示「子行数」徽标与 `字段 Σ 值` 聚合徽标；点分组行收起/展开；非分组列在分组行上显示聚合值（配了 `aggregations` 的列）或占位。

完整示例（订单聚合页）：

```json
{ "component": "table", "title": "全部订单",
  "rows": "/systems/back/data/orders.json",
  "searchable": true, "sortable": true,
  "groupBy": "category",
  "aggregations": { "amount": "sum", "qty": "sum" },
  "column": [
    { "field": "id", "label": "订单号" },
    { "field": "product", "label": "商品" },
    { "field": "category", "label": "品类" },
    { "field": "qty", "label": "数量", "align": "right" },
    { "field": "amount", "label": "金额", "align": "right" },
    { "field": "date", "label": "日期" },
    { "field": "status", "label": "状态" }
  ]}
```

### 7.5 图表（Unovis）

| 组件 | 专属属性 |
|---|---|
| `chart-area`（缺省） / `chart-line` | `xKey`、`yKeys` 或 `series`、`areaOpacity`(面积透明度，缺省 0.16) |
| `chart-bar` | `xKey`、`yKeys` 或 `series`（多序列自动并列） |
| `chart-donut` | `categoryKey`（类目字段）、`valueKey`（数值字段） |

公共属性：`data`（数组或 `/file.json`）、`height`(px，缺省 260)、`colors`（颜色数组，缺省用主题色板）。

序列的两种声明（二选一）：

```json
{ "component": "chart-area", "data": "/systems/back/data/risk-trend.json",
  "xKey": "date", "yKeys": ["high", "medium"], "height": 280 }
```

```json
{ "component": "chart-area", "data": "/systems/userfront/data/monthly-spend.json",
  "xKey": "month", "height": 260,
  "series": [ { "key": "spend", "label": "消费" }, { "key": "budget", "label": "预算" } ] }
```

```json
{ "component": "chart-donut", "data": "/systems/back/data/alert-types.json",
  "categoryKey": "label", "valueKey": "value", "height": 200 }
```

### 7.6 导航与反馈

- `menu-tree` / `breadcrumb-auto`：只出现在 desktop 插槽里，无需配置（menu.json 驱动菜单，面包屑由导航自动派生）。
- `alert` 见 §7.2。`fallback-display`：未知组件/字段时的占位提示（框架自动使用，一般不手写）。

### 7.7 注册名总表（component 可写值）

| 分组 | 注册名 |
|---|---|
| 基础 | `text` `heading` `link` `icon` `image` `button` `badge`（=`tag`） `separator`（=`divider`） `field-value` |
| 卡片 | `card` `card-header` `card-title` `card-description` `card-content` `card-footer` |
| 表单 | `form`（=`schema-form`） `label` `input` `textarea` `input-number` `switch` `checkbox` `select` `radio-group` `slider` `date-picker` `form-item` |

## 8. 导航与面包屑

**触发方式**（殊途同归，全部走同一个 `navigate()`）：

1. 菜单点击（menu.json 的 `pageId`）；
2. 任意节点写 `"@goto": "<目标id>"`——典型是「返回列表」按钮：

```json
{ "component": "button", "text": "返回列表", "variant": "secondary", "@goto": "user-list" }
```

**目标类型语义**：

| 目标 | 行为 |
|---|---|
| page | 纯激活切换：当前页实例切到目标页，**不发生树变更**（最快、无副作用） |
| component 等非 page | 覆盖式：克隆目标节点放到原 page 的位置，目标原件保留原位 |

**面包屑**：全自动。进入 page 入栈；导航到面包屑中已有的 page 时**截断回跳**（后面的层级丢弃）；切换系统重置为首页。无需任何配置。

## 9. 页面状态机（pages/*.sm.md）

page 节点声明 `"stateMachine": "/systems/<id>/pages/<名>.sm.md"` 后，页面获得事件驱动的状态流转能力。

### 9.1 表格结构（完整规范）

```markdown
| 组件 / 事件 | 浏览（初始） | 编辑中 | 审核中 |
|---|---|---|---|
| userInfo | .lock==true | .lock==false | .lock==true |
| btnEdit | | @click | |
| btnSave | @click | | |
| btnSubmit | | | @click |
| === | === | === | === |
| txtUser | .readOnly=true | .readOnly=false | .readOnly=true |
| btnSubmit | .enabled=false | .enabled=true | .enabled=false |
| userInfo | | .lock=false | |
| form | | | .reset() |
```

- **表头**：第一列固定写「组件 / 事件」；其余列 = 状态。初始状态在列名后标注 `（初始）`，省略则取第一列（会给警告）。
- **`===` 分区线**：整行 `===`（必须存在）。上方 = 触发区，下方 = 响应区。
- **触发区单元格**：
  - `@事件名` —— 声明「在该状态下，该组件发出此事件 → 转移到本列状态」。事件两种：`@click`（按钮点击）、`@change`（受控控件值变化）。
  - `.prop 表达式` —— 转移条件（如 `.lock==true`）；同状态同组件写多行条件会报错。
  - 转移规则：事件声明在哪个状态列，触发后就转移到那列；条件全过且唯一才转移，0 个候选忽略，多个候选视为定义歧义（报错不转移）。
- **响应区单元格**（进入该列状态后执行）：
  - `.prop=值` —— 写组件绑定属性，多语句用 `;` 分隔。
  - `.方法()` —— 调用方法，目前内置 `reset()`（恢复播种值）。
- **可写的控制属性**：`visible` / `enabled` / `readOnly` / `text` / `value`，以及模型业务字段平铺（如 `.lock`）。
- **转义**：单元格里出现 `|`（如逻辑或）必须写 `\|`。

### 9.2 绑定机制

- 触发区/响应区第一列的组件 id（如 `btnEdit`、`userInfo`、`form`）会与页面 JSON 中**同 id 的节点**绑定。
- `id` 不在页面 JSON 中的称为**虚拟组件**（如上例的 `form`、`userInfo`）：只作为数据/逻辑载体存在，其 `reset()` 会重置页面全部实体绑定。加载期会给出 warning 提示。
- `userInfo` 这类虚拟组件的播种：页面 JSON 中若有同 id 节点的 `value` 则用之；否则表单类播种 `{value:''}`；文本类播种 `{text}`。
- `$state`（当前状态名）与 page 的 `constants`（如 `$currentUserName`）自动注入条件/响应表达式的作用域。

### 9.3 幂等转移

目标状态 = 当前状态时，若该列响应区非空则**重新执行**（利用 `.reset()` 做「提交后重置」语义）。

### 9.4 受控事件

状态机绑定的控件（`input`/`select`/`switch` 等 CONTROL 组件）值变化会自动发 `change` 事件；按钮点击发 `click`。组件只有在某状态列声明了对应事件才会被监听（未声明的组件点击不产生转移）。

### 9.5 运行期反馈

解析/校验问题（缺分区线、状态重名、引用不存在的组件 id 等）以 error/warning 形式打印在浏览器控制台，带 `[state-machine]` / `[metadata]` 前缀，**不会中断页面渲染**。

## 10. 常用配方

### 10.1 新增一个页面（checklist）

1. `systems/<系统id>/<系统id>.page.json` 的 desktop children 里加一个 page 节点（`type:"page"`、`slot:"content"`、唯一 `id`、`title`、`component:"page-default"`）；
2. 菜单 JSON 里加菜单项（`pageId` 指向它）；
3. 刷新浏览器（新系统目录首次出现时重启 `npm run dev`）。

### 10.2 新增一个系统

1. `systems/index.json` 加 `{ "id": "xxx", "label": "名称" }`；
2. 建目录 `systems/xxx/`，放 `xxx.menu.json` + `xxx.page.json`（页面配置两种形态任选，§4.2）；
3. 有模型就加 `models/*.ts`（dev 会自动重新生成元数据）。

### 10.3 详情页（只读展示 + 返回）

```json
{ "type": "page", "id": "user-detail", "slot": "content", "title": "用户详情",
  "component": "page-default", "children": [
    { "component": "descriptions", "data": "@@User", "mode": "readonly", "value": { "...": "..." } },
    { "component": "button", "text": "返回列表", "variant": "secondary", "@goto": "user-list" }
  ]}
```

### 10.4 权限不足的禁用表单

form 或其任意祖先写 `"mode": "disabled"`，全部控件自动禁用（§6.1）。

### 10.5 统计卡 + 图表看板

`row columns:4` 放 4 个 stat-card → `row template:"1.75fr 1fr"` 放 chart-area + chart-donut → `row columns:1` 放 chart-bar。参照 `systems/back/back.page.json` 的 dashboard 页。

## 11. 排错速查

| 现象 | 原因与处理 |
|---|---|
| 页面显示 `[未知组件: xxx]` | `component` 名拼写错误（对照 §7 注册名） |
| 表格/表单没有列/字段 | `@@Type` 引用的类型没进元数据：确认 `models/*.ts` 里存在该 class 且 `npm run gen:metadata` 已跑（dev/build 自动） |
| 控制台 `[metadata] 未找到类型` | 同上；或类型写错系统前缀 |
| 状态机不转移 | 事件没声明在「当前状态」列；或条件不满足；或同状态多候选歧义（控制台有 `[state-machine]` 报错） |
| 切系统报「缺少 desktop 节点」 | page.json 既没有 `desktop` 包装、根节点也不是 `type:"desktop"`（§4.2） |
| 改了 JSON 没生效 | 刷新浏览器；新目录/新系统需重启 `npm run dev` |
| 卡片标题/表单按钮不显示 | 子节点忘了写 `"slot"`（§4.5：header 内容要写 `"slot":"header"`，form 按钮行要写 `"slot":"footer"`） |

调试出口：浏览器控制台 `window.__pp` 提供 `appState`（当前系统/页面）与 `getTreeIndex`（id → 节点索引）。
